Release 0.15.1#

Release summary#

Release 0.15.1 is a maintenance release of statsmodels 0.15. It collects the bug fixes, stricter checks of function arguments and smaller enhancements that were merged into main after the v0.15.0 tag (2026-08-27). Most changes correct results or error messages that were wrong or unhelpful in 0.15.0. Two arguments are deprecated and continue to work with a FutureWarning.

statsmodels is using github to store the updated documentation. Two versions are available:

  • Stable, the latest release

  • Development, the latest build of the main branch

Release Statistics#

  • Pull requests merged: 259

  • Time span: 2026-08-27 through 2026-10-24

Breaking Changes and Deprecations#

Deprecations#

  • The return_df argument of acorr_ljungbox has no effect, since the function always returns a DataFrame. Passing it now raises a FutureWarning, and it will be removed in statsmodels 0.17.0. Issue #8968, PR #10549

  • The linear argument of predict in BinomialBayesMixedGLM, PoissonBayesMixedGLM and BayesMixedGLMResults is deprecated in favor of which, matching predict. Use which="linear" instead of linear=True and which="mean" instead of linear=False. Passing linear now raises a FutureWarning, and it will be removed in statsmodels 0.17.0. The value of which is case sensitive and exog can be a list. Issue #8562, PR #10554, PR #10555

  • Passing a row, an array with shape (1, n) or (1, …, 1, n) with n > 1, as x to recursive_filter is deprecated, since x must be 1-D or an (n, 1) column. The row is still filtered as a 1-D series of n observations and returned with the shape of x, and init now works with it instead of raising a ValueError. Passing a row now raises a FutureWarning, and it will raise a ValueError in statsmodels 0.17.0. Pass a 1-D array or an (n, 1) column instead. PR #10810

  • statsmodels.tsa.statespace.tools.set_mode, statsmodels.tsa.tsatools.unintegrate and unintegrate_levels, and statsmodels.tsa.vector_ar.output.normality_summary and hypothesis_test_table are deprecated. Nothing in statsmodels uses them and they are neither exported nor documented. Calling them now raises a FutureWarning, and they will be removed after statsmodels 0.17. PR #10828

  • The statsmodels.tsa.arima_model module, whose ARMA and ARIMA classes were removed in statsmodels 0.13 and only raise NotImplementedError, will be removed after statsmodels 0.16. Use statsmodels.tsa.arima.model.ARIMA or statsmodels.tsa.statespace.sarimax.SARIMAX. PR #10828

  • distance_indicators with x of more than one dimension issues a FutureWarning and returns the same result as before. After statsmodels 0.17, a column will give the result of the 1-D series and other input will raise. PR #10858

  • A bool p in c_sja and c_sjt, and so det_order=True in coint_johansen, is deprecated. It is still used as 0 or 1, with a FutureWarning, and will raise after statsmodels 0.17. PR #10859

  • The return_results argument of coint is deprecated. It has no effect, issues a FutureWarning when it is not None, and will be removed after statsmodels 0.17 is released. PR #10848

  • 2-D lag polynomials that the functions of statsmodels.tsa.arima_process accepted, for example a column in arma_periodogram or a row in index2lpol, are deprecated. They give the same result as before with a FutureWarning, and will raise after statsmodels 0.17. PR #10861

  • arma_periodogram and ArmaProcess.periodogram divide by sqrt(2 * pi) instead of 2 * pi. A new normalization argument selects "2pi" (the spectral density) or "sqrt(2pi)" (the current result). Without it, a FutureWarning is issued, and the default will change to "2pi" after statsmodels 0.17. PR #10863

Behavior changes#

  • MixedLM.score_sqrt is private. PR #10700

  • OaxacaResults.summary() returns the summary as a string instead of printing it and returning None. Use print(result.summary()) to display it. Issue #7733, PR #10491

  • NegativeBinomial in statsmodels.discrete.discrete_model raises a TypeError if the alpha keyword is passed. The dispersion parameter is estimated jointly with the regression coefficients, and a value passed as alpha was silently ignored. PR #10427

  • The cov_type values "HC1", "HC2" and "HC3" are only implemented for linear regression models. For other models, for example GLM and the discrete models, HC0 was used silently while the results reported the requested cov_type. Now a SpecificationWarning is issued and the results report cov_type="HC0". The warning is attributed to the calling code, and its message gives a scaling_factor that matches the heteroskedasticity robust covariance of Stata. Issue #7798, PR #10523, PR #10580

  • acorr_ljungbox raises a ValueError if a requested lag is smaller than 1. A lag of 0 silently returned the statistic of the largest lag. Lags that are not smaller than the number of observations also raise a ValueError now instead of failing with an array broadcasting error. The error messages name the lag that was passed. PR #10481, PR #10311, PR #10561

  • The DataFrame returned by predict of the results of MNLogit, when exog is a DataFrame or the model was fit with a formula, has the categories of endog as columns, in the order of wendog with the reference category first, instead of 0, 1, …, J - 1. The categories keep their type, so model.names and the labels in summary are strings but the columns of predict are, for example, integers for integer endog. Predictions for an array exog are still arrays. Issue #4804, PR #10587

  • With missing="drop", a MissingDataError is raised if all observations are dropped because of missing values. An unknown value of missing raises a ValueError. Issue #4417, PR #10535, PR #10407

  • The name of the column "Cont. Int. Hi." in the data frame returned by DiscreteMargins.summary_frame is corrected to "Conf. Int. Hi.". PR #10506

  • anova_lm raises a ValueError for a single model with a rank-deficient design matrix, for example a duplicated column, an empty cell of an interaction or more columns than observations. The Type I, II and III tables of such a model assigned arbitrary sums of squares, degrees of freedom and p-values to the redundant terms. The weighted design matrix is checked, so a factor level that only appears in observations with zero weight is also rejected. Issue #5398, Issue #8506, PR #10340, PR #10622

  • information returns the positive definite expected (Fisher) information matrix X' W X / scale as documented for LikelihoodModel.information. It previously returned the negative of this matrix, which is the expected Hessian. This affects all families and links, also GLMGam. The result is the expected information also for non-canonical links, where it differs from the observed information -model.hessian(params). To get the old value, use model.hessian(params, observed=False), or -model.information(params). Issue #7826, PR #10498, PR #10628

  • A two-level categorical response, such as a bool, str or Categorical column, in a formula for GLM with the Binomial family now models the probability of the second level, as the glm function of R does. The expanded indicator columns of both levels were read as (successes, failures), so the first level was modeled and the signs of all coefficients were reversed. endog_names shows the modeled level. Other families, and a response with a single level in the data, raise a ValueError. Issue #10501, PR #10503, PR #10635

  • The bandwidths of discrete variables that are selected by KDEMultivariate, KDEMultivariateConditional and KernelReg (bw="normal_reference", "cv_ml", "cv_ls" and "aic") are kept in the range for which the kernels are defined: at most (levels - 1) / levels for an unordered variable and less than 1 for an ordered variable. The normal reference rule of thumb scaled with the numeric codes of a discrete variable, so that the density was negative, and the cross-validation returned bandwidths outside of the range. The cross-validation searches the best bandwidths inside the range, also in KernelReg where the bandwidths of discrete variables were not bounded. The default bandwidth still depends on the numeric codes. Issue #3790, PR #10515, PR #10641

  • banddepth with method="BD2" computed the pairs of curves that contain a curve from the ranks of the curve at each point. This is wrong if curves cross or have equal values, since the same two curves have to bound the curve at all points. The depth now counts the pairs of curves that contain the curve at all sampled points, with values equal to a bounding curve counted as inside, so the depth of such data changes. Curves are not interpolated, so only the sampled values matter. data can be any array_like, for example a DataFrame. Issue #7105, PR #10513, PR #10638

  • banddepth with method="MBD" counts values equal to a band boundary as inside. Previously, tied values were assigned arbitrary ranks, so depths could depend on the input row order. The depths of data with tied values change. PR #10691

  • Many functions in statsmodels.stats, statsmodels.tsa and other modules now raise a ValueError for invalid arguments that were accepted before, see Stricter Input Validation below.

  • KDEUnivariate.evaluate with a kernel of bounded support ("epa", "tri", "uni", "biw", "triw", "tric", "cos" and "cos2") returns one density per point, which is 0.0 where no observation is in the support of the kernel. It returned a scalar nan for the whole array of points if one of them was outside the support of all observations. cdf and entropy, and so sf and cumhazard, of these kernels returned nan for most data. They now integrate the density over the support of the observations, in the units of the data, so that the cdf starts at 0 and ends at 1. Issue #7195, PR #10632

  • filter, smooth and fit of state space models with a stationary initialization raise a LinAlgError if a parameter is fixed at a unit root, for example with fix_params, instead of returning results with an llf of 0.0 that were computed from an initial state covariance with negative variances. Loglikelihoods at parameters with a valid stationary covariance are unchanged, but the fit of a very ill-conditioned model, whose optimizer used to survive negative covariances along its path, can end at a different optimum. For example, a SARIMAX model with order=(15, 0, 0) and trend="c" for np.linspace(0, 2 * np.pi, 1000) ends at an llf of 1667.85 instead of 6835.06. Issue #5459, PR #10747

  • powerdiscrepancy with lambd=0 ("loglikeratio", the default, which is the G-test) returns valid test statistics when observed counts contain zeros, evaluating \(x \ln(x)\) to 0, instead of returning (nan, nan). Issue #10703, PR #10704

  • In-sample MNLogit results predictions with exog omitted return a DataFrame with the training row index and response categories as columns when the model was fit with pandas data (endog or exog) or with a formula, including a formula on a dict or a recarray (the index is then 0, 1, …, nobs - 1). Previously, these predictions were ndarrays. Models fit with NumPy data and no formula, and predictions with explicit NumPy exog, still return ndarrays. Use np.asarray on the predictions if an ndarray is needed. Issue #4541, PR #10735

  • powerdiscrepancy (and the G-test) with lambd=0 returns valid test statistics when observed counts contain zeros, evaluating \(x \ln(x)\) to 0, instead of returning (nan, nan). Issue #10703, PR #10704

  • The bias correction (third) step of hannan_rissanen filters the second-step residuals with the inverse of the MA polynomial, \(\theta(B) W_t = Z_t\), as in Brockwell and Davis (2016), section 5.1.4. Previously \(W_t\) was a first-order approximation of this filter. This changes the estimated coefficients whenever the third step is applied, which is the default (unbiased=None) if the second-step estimates are stationary and invertible. The estimates are closer to the maximum likelihood estimates: for 50 simulated ARMA(2, 1) series with 1000 observations the median distance to the estimates of ARIMA(..., trend="n").fit() fell from 0.083 to 0.020. This also changes the final estimates of ARIMA.fit(method="hannan_rissanen") and of gls with arma_estimator="hannan_rissanen". It changes the starting parameters of arma_estimator="innovations_mle" (ARIMA.fit(method="innovations_mle") and the default of gls), but not their final estimates, which agree up to the tolerance of the optimizer. If the corrected parameters are non-stationary or non-invertible, the second-step estimates are returned with an EstimationWarning. Issue #6159, PR #10712

  • diebold_mariano_test raises a ValueError for inputs for which it returned a meaningless result or raised another exception before. This is the case if the loss differential is constant up to rounding error, for example if the two forecasts are identical (nan before, or a huge statistic with a p-value of 0 if the forecast errors are constant); if lags is not smaller than the number of observations, or horizon is not smaller than it when lags is not given or harvey_adj=True (a statistic that is not meaningful before, which is 0 with harvey_adj=True if horizon is the number of observations or one more); and if criterion does not return one loss per observation (a TypeError before for a scalar, otherwise a statistic from a loss series of the wrong length). The results that were returned for other input are unchanged. Issue #10753, PR #10755

  • acf and pacf return 1.0 for lag 0 and nan for lags 1 and higher when the input series is constant, for every method of pacf. Before, acf returned nan at all lags if the mean of the series is exactly representable, and otherwise autocorrelations close to 1 caused by the rounding error of the mean, for example 0.99 at lag 1 for 100 observations of 101.37. pacf returned numbers or nan depending on the method and the constant. ccf returns nan for all lags when either series is constant. The qstat and pvalues of acf(..., qstat=True) and the statistics and p-values of acorr_ljungbox are nan for a constant series. Issue #10647, PR #10701

  • Newton’s method (method="newton", which is the default of the discrete models and PHReg) shortens a step that gives a log-likelihood that is not finite or lower. Fits that did not take such a step are unchanged. Fits from starting values for which the full steps diverge or need many iterations, for example Poisson with a large exog and zeros as starting values, now converge. If no step is found, the fit stops at the last parameters with converged False and a ConvergenceWarning, where the parameters were nan and converged was True. A step that is not a direction of descent, for example because the Hessian is not positive definite, is only taken if it decreases the log-likelihood, and the iteration stops if the change of the parameters of the full Newton step, not that of a shortened step, is at most tol. GLM.fit with method="newton" shortens only a step that is not finite if the link is not the canonical link of the family. PR #10605

  • GLM.fit_regularized scaled the log-likelihood by the number of rows instead of the sum of the freq_weights, for method="elastic_net", method="l1_slsqp" and the ridge fit with L1_wt=0. With frequency weights this changed the effective penalty, so the estimates and the selected variables differed from the fit on the data with each row repeated according to its weight. The estimates of existing fits with freq_weights change. The estimates of fits without freq_weights are unchanged. PR #10705

  • GLM.fit_regularized with L1_wt=0 (the ridge fit) used the scale estimated at the current parameters in the log-likelihood and the score, where the fits with L1_wt greater than 0 and method="l1_slsqp" use a scale of 1. For families with an estimated scale, for example Gaussian, Gamma and Tweedie, the estimates differed from the solution of the penalized problem, for example from the closed-form ridge estimate of the linear model, and the fit often warned that the optimization may have failed. The ridge fit now uses a scale of 1, so that its estimates change for these families, by much if the estimated scale is far from 1. The estimates of Binomial, Poisson and NegativeBinomial, which have a fixed scale, are unchanged. Multiplying alpha by the scale estimated at the estimates gives the penalty of earlier versions, where that fit converged; the example of GLM.fit_regularized shows how. PR #10776

  • The marginal effects of GEE results fit with use_t=True use the t distribution with df_resid_inference degrees of freedom, as the parameters do. Their p-values and confidence intervals change, and the z and Pr(>|z|) columns of summary_frame are named t and Pr(>|t|). Results with the default use_t=False are unchanged. PR #10792

  • ExponentialSmoothing in statsmodels.tsa.holtwinters with trend="mul", damped_trend=True and seasonal="add" estimated its parameters by minimizing residuals computed with l * phi * b instead of l * b**phi, while the fitted values, the reported sse and the forecasts use l * b**phi. The estimates of this model now minimize the reported sse, so its parameters, fitted values and forecasts change, for example the sse of a fit to the first 240 months of the co2 data falls from 590.8 to 27.0. Results of all other trend, damping and seasonal combinations are unchanged. PR #10829

  • recursive_filter filters an (n, 1) column, such as a one-column DataFrame, along its rows and returns the values of the 1-D series. Before, no recursion was applied to a column, which was returned unchanged without an error, and init raised a ValueError. Input with more than one row and more than one column, which was filtered across the columns of each row, now raises a ValueError. So does input with more than two dimensions that is neither a row with shape (1, …, 1, n) nor a single observation with shape (1, …, 1), such as an (n, 1, 1) array, which was returned unchanged. Results for 1-D input are unchanged. PR #10810

  • The lags arguments of the ArmaProcess methods acovf, acf, pacf, periodogram, impulse_response, arma2ma and arma2ar raise a ValueError for values below 1. Before, lags=0 was taken as the default and returned nobs values, and a negative value gave a numpy error or an empty result. An integral float is now accepted by all of them. PR #10835

  • pacf_burg (and pacf with method="burg"), kpss with regression="c", range_unit_root_test, pccf and q_stat treat an (nobs, 1) column, such as a one-column DataFrame, as the 1-D series instead of raising, and raise a ValueError for input with more than one column. q_stat silently took a (1, k) row as k values at lag 1 and gave wrong statistics; it now raises. Results for 1-D input are unchanged. PR #10837

  • ccf and ccovf treat an (nobs, 1) column, such as a one-column DataFrame, as the 1-D series. Before, two columns gave a meaningless 2-D result without an error, for example an (nlags, nobs) array from ccf, and a column next to a 1-D series raised an error from SciPy. Input with more than one column now raises a ValueError. Results for 1-D input are unchanged. PR #10811

  • pccf with method="yw" or "ywm" (the default) no longer depends on the scales of x and y: rescaling one series, for example by 1e8, made every lag nan. Series that are collinear to working precision give nan for every lag, as exactly collinear series did, instead of inaccurate values. When the recursion reaches a singular prediction error covariance matrix, the later lags are nan on every platform; before, they depended on rounding, and the lag computed just before could be dropped. Results for other input change only by rounding. PR #10843

  • When den is longer than num, deconvolve returns an empty ndarray instead of a list as the quotient, and a float (or complex) copy of num as the remainder instead of num itself. The values are unchanged. PR #10864

  • arma_pacf, arma_impulse_response, arma2ma and arma2ar raise a ValueError for lags below 1, as the ArmaProcess methods do since PR #10835, instead of NumPy errors, and arma_periodogram raises for an integer worN below 1 instead of returning empty arrays. ArmaProcess.from_estimation no longer replaces nobs=0 with the number of observations of the results. PR #10860

  • ArmaProcess.generate_sample uses the nobs of the process as the default sample size, as documented, instead of 100. Processes created with another nobs, including those from ArmaProcess.from_estimation, now generate nobs values when nsample is not given. PR #10862

  • levinson_durbin with isacov=True and diebold_mariano_test treat an (nobs, 1) column, such as a one-column DataFrame, as the 1-D series instead of raising, and raise a ValueError for input with more than one column. Results for 1-D input are unchanged. PR #10849

  • The default nlags of acf with missing="drop" or "conservative" counts only the non-missing observations. It counted the NaNs, so it could return more lags, or raise when nlags was not given. The values at each lag are unchanged. PR #10847

New Features and Enhancements#

New functions and methods#

  • Add compare_vuong, the Vuong test for non-nested likelihood models, and its result class VuongTestResult. The test supports AIC and BIC corrections and one-sided alternatives. The function is available from statsmodels.stats.api. Issue #3897, PR #10502, PR #10560

  • Add confint_proportions_paired for the confidence interval of the difference of two paired proportions, using Newcombe’s method 10 (the default) or the Wald interval. Issue #10374, PR #10375

  • Add RollingRegressionResults.get_resid to compute the residuals of RollingOLS and RollingWLS, optionally as one-step ahead prediction errors with out_of_sample=True. Issue #7521, PR #10462

  • Add the keyword-only argument effect_group to TreatmentEffect.aipw and TreatmentEffect.aipw_wls to estimate the effect on the treated (ATET) or on the controls (ATC) in addition to the average treatment effect (ATE), which remains the default. Issue #10226, PR #10233

  • Add the methods TreatmentEffect.overlap_summary and TreatmentEffect.balance_table. They report the distribution of the propensity score by treatment group and the covariate balance before and after inverse probability weighting. Issue #10234, PR #10235

  • MNLogit has the documented names attribute that maps the column number of wendog to the name of the category of the endogenous variable. Issue #8995, PR #10486, PR #10558

  • DynamicFactorMQ.fit_em(full_output=True) includes a converged entry in the EM return values, which distinguishes a converged fit from a fit that stopped at maxiter or was reverted. Issue #10157, PR #10214

  • statsmodels.tsa.tsatools.freq_to_period supports sub-daily frequencies, for example hourly data maps to 24 and "5min" to 288, if the multiplier divides the day. It also supports the business month, quarter and year frequencies ("BME", "BQS", "BYE", "CBMS" and similar), which map to the same period as their calendar counterparts, including the older pandas spellings. Issue #9619, Issue #9308, Issue #10525, PR #10401, PR #10528, PR #10542

  • statsmodels.tsa.tsatools.add_lag accepts the label of a column of a pandas DataFrame as col. PR #10302

  • Add MultiComparison.dunnett_t3 for Dunnett’s T3 test of all pairwise comparisons of means with unequal variances. The p-values and the simultaneous confidence intervals use the studentized maximum modulus distribution with the Welch degrees of freedom of each pair. The plot_simultaneous method of the results raises NotImplementedError. Issue #9472, PR #10469

  • Add the one_sided argument to hpfilter. With one_sided=True, the trend at time t only depends on the observations up to and including t. It is computed with the Kalman filter of the state space form of the HP filter. Issue #6947, PR #10588

  • Add vif, vif_ridge and collinear_index for the diagnosis of multicollinearity. They are available from statsmodels.stats.api. vif computes the variance inflation factors of all columns of a data matrix, or of a covariance or correlation matrix, with one eigenvalue decomposition. It is about 90 times faster than variance_inflation_factor called for each column for 20 variables and 1000 observations, about 300 times faster for 60 variables, and returns a Series for a DataFrame. Issue #1669, PR #2380, PR #7711, PR #10623

  • Add krippendorff_alpha, Krippendorff’s alpha for the agreement of any number of raters, with missing ratings, for nominal, ordinal, interval and ratio data. It is available from statsmodels.stats.api. PR #10738

  • Add the arguments alternative and kernel to diebold_mariano_test. alternative selects a one-sided test, "larger" if forecast_b is more accurate or "smaller" if forecast_a is. kernel="uniform" estimates the long-run variance with equal weights up to lags, as in Diebold and Mariano (1995) and Harvey et al. (1997), and uses horizon - 1 lags by default; a ValueError is raised if its estimate of the variance is not positive. With harvey_adj=True this gives the results of dm.test in the R package forecast. The results of the default arguments are unchanged. Issue #10753, PR #10755

  • Add clark_west_test, the test of Clark and West (2007) of equal predictive accuracy of nested models, and its result class ClarkWestResult. It adjusts the mean squared prediction error of the larger model for the noise from estimating parameters that are zero under the null, which biases the comparison of the unadjusted errors, for example with diebold_mariano_test, against the larger model. The function is available from statsmodels.tsa.api. Issue #10754, PR #10756

  • Add the option step_halving to fit(method="newton"). It is True to halve a step, up to 30 times, that gives a log-likelihood that is not finite or lower, "finite" to halve only a step that is not finite, and False for the full Newton step. The default is True, and GLM uses "finite" if the link is not the canonical link of the family. PR #10605

  • Add the option use_t to GEE.fit, OrdinalGEE.fit and NominalGEE.fit. With use_t=True, p-values, confidence intervals, t_test and f_test use the t distribution with the number of groups minus the number of parameters as degrees of freedom. Issue #8610, PR #10781

  • Add cov_type="kauermann_carroll" to GEE.fit, the Kauermann-Carroll small-sample correction of the robust covariance. It scales the residuals of each group by the inverse square root of one minus the leverage, where "bias_reduced" (Mancl-DeRouen) uses the inverse. Issue #1183, PR #10781

  • Add cov_type="fay_graubard" and cov_type="morel_bokossa_neerchal" to GEE.fit, the small-sample corrections of the robust covariance of Fay and Graubard (2001) and Morel, Bokossa and Neerchal (2003), with the constants b = 0.75, d = 2 and r = 1. Issue #1183, PR #10794

Performance#

  • RollingOLS and RollingWLS estimate the windows in batches using stacked linear algebra. The pull request reports speed-ups of 5 to 30 times. Issue #8417, PR #10533

  • The leave-one-observation-out measures of OLSInfluence (dfbeta, dfbetas, dffits, resid_studentized_external, cov_ratio and summary_frame) are computed from closed form updates instead of estimating one regression for each observation if the model is OLS or WLS and exog has full rank. Issue #9009, PR #10367

  • adfuller with autolag selects the lag length from a single QR decomposition and needs much less memory and time for large maxlag. This also applies to coint and zivot_andrews. Issue #1849, PR #10526

  • acorr_ljungbox computes the autocorrelations using the FFT, which is faster for long series. PR #10470

  • robust.scale.qn_scale is about 5 times faster for large samples. PR #10244

  • KDEMultivariateConditional.cdf and KDEMultivariateConditional.imse evaluate the kernel of the exogenous variables only once for each observation. The bandwidth selection with bw="cv_ls" is about 2 times faster with one continuous exogenous variable and about 3.5 to 4 times faster with two exogenous variables, and cdf is about 1.5 to 2 times faster. Issue #6076, PR #10626

  • Lag order selection fits the nested sequence of models from a single blocked QR decomposition, shared by a new private helper. This applies to adfuller with autolag, VAR.select_order, pacf_ols, pacf_yw (Levinson-Durbin) and ardl_select_order. VAR.select_order is 12 to 43 times faster, pacf_ols about 90 times faster for long series, and ardl_select_order evaluates thousands of candidate models in a fraction of a second instead of seconds. pacf_ols with efficient=True demeans the series first, which is more accurate when the mean is large relative to the variation. Issue #2276, PR #10571

  • zivot_andrews computes the regressions of all candidate break periods from one QR decomposition of the regressors that do not depend on the break, instead of fitting one regression per period. The cost grows linearly instead of quadratically with the number of observations, so the test is about 25 to 65 times faster for 2,000 observations and 50 to 140 times faster for 5,000. The statistics are more accurate when the regressors are close to collinear, so for such series the statistic can change in the later digits. The new values agree with R (urca) and with high-precision arithmetic. Issue #10601, PR #10602, PR #10624

  • OLS, WLS and GLS have the new fit option method="chol", which solves the normal equations with a Cholesky factorization of the k x k cross product matrix of the whitened regressors instead of computing the pseudoinverse or the QR factorization of the n x k design matrix. For 3,000,000 observations and 10 regressors, fit is about 20 times faster than with the default method="pinv", and creating and fitting the model needs more than 10 times less peak memory: the fit itself allocates no array of the size of the design matrix, while "pinv" and "qr" need about three times its size. The method squares the condition number of the design with unit-norm columns and is less accurate than "pinv" and "qr" on ill-conditioned designs, for example with an uncentered regressor with a large mean next to the constant; it should only be used when speed and memory usage matter more than numerical accuracy, see the Notes of fit. Collinear regressors by the tolerance of R’s lm fall back to the pseudoinverse with a SingularMatrixWarning. The pseudoinverse pinv_wexog is only computed when a covariance estimator or an influence measure needs it. Issue #9317, PR #10679

  • get_margeff with the default at="overall" computes the delta method Jacobian of the average marginal effects directly instead of averaging the Jacobian at each observation. Regression and linear models#

  • OLS.fit did not detect an exactly rank-deficient design, for example a duplicated constant, from about 1,000 observations on. The smallest singular value of such a design is a few multiples of the machine precision times the largest, independent of the number of observations, and was above the fixed cutoff. No SingularMatrixWarning was issued and the parameters were of the order of 1e12. The rank is now the number of singular values above max(nobs, k) * eps times the largest, the rule of numpy.linalg.matrix_rank. This is used for the rank and for the pseudoinverse in both method="pinv" and method="qr". Designs with a condition number above about 1 / (nobs * eps) are now treated as rank-deficient and the minimum-norm solution is returned. PR #10714
