Release 0.15.1#

Release summary#

Release 0.15.1 is a maintenance release of statsmodels 0.15. It collects the bug fixes, stricter checks of function arguments and smaller enhancements that were merged into main after the v0.15.0 tag (2026-08-27). Most changes correct results or error messages that were wrong or unhelpful in 0.15.0. Two arguments are deprecated and continue to work with a FutureWarning.

statsmodels is using github to store the updated documentation. Two versions are available:

  • Stable, the latest release

  • Development, the latest build of the main branch

Release Statistics#

  • Pull requests merged: 259

  • Time span: 2026-08-27 through 2026-10-24

Breaking Changes and Deprecations#

Deprecations#

  • The return_df argument of acorr_ljungbox has no effect, since the function always returns a DataFrame. Passing it now raises a FutureWarning, and it will be removed in statsmodels 0.17.0. Issue #8968, PR #10549

  • The linear argument of predict in BinomialBayesMixedGLM, PoissonBayesMixedGLM and BayesMixedGLMResults is deprecated in favor of which, matching predict. Use which="linear" instead of linear=True and which="mean" instead of linear=False. Passing linear now raises a FutureWarning, and it will be removed in statsmodels 0.17.0. The value of which is case sensitive and exog can be a list. Issue #8562, PR #10554, PR #10555

Behavior changes#

  • OaxacaResults.summary() returns the summary as a string instead of printing it and returning None. Use print(result.summary()) to display it. Issue #7733, PR #10491

  • NegativeBinomial in statsmodels.discrete.discrete_model raises a TypeError if the alpha keyword is passed. The dispersion parameter is estimated jointly with the regression coefficients, and a value passed as alpha was silently ignored. PR #10427

  • The cov_type values "HC1", "HC2" and "HC3" are only implemented for linear regression models. For other models, for example GLM and the discrete models, HC0 was used silently while the results reported the requested cov_type. Now a SpecificationWarning is issued and the results report cov_type="HC0". The warning is attributed to the calling code, and its message gives a scaling_factor that matches the heteroskedasticity robust covariance of Stata. Issue #7798, PR #10523, PR #10580

  • acorr_ljungbox raises a ValueError if a requested lag is smaller than 1. A lag of 0 silently returned the statistic of the largest lag. Lags that are not smaller than the number of observations also raise a ValueError now instead of failing with an array broadcasting error. The error messages name the lag that was passed. PR #10481, PR #10311, PR #10561

  • The DataFrame returned by predict of the results of MNLogit, when exog is a DataFrame or the model was fit with a formula, has the categories of endog as columns, in the order of wendog with the reference category first, instead of 0, 1, …, J - 1. The categories keep their type, so model.names and the labels in summary are strings but the columns of predict are, for example, integers for integer endog. Predictions for an array exog are still arrays. Issue #4804, PR #10587

  • With missing="drop", a MissingDataError is raised if all observations are dropped because of missing values. An unknown value of missing raises a ValueError. Issue #4417, PR #10535, PR #10407

  • The name of the column "Cont. Int. Hi." in the data frame returned by DiscreteMargins.summary_frame is corrected to "Conf. Int. Hi.". PR #10506

  • Many functions in statsmodels.stats, statsmodels.tsa and other modules now raise a ValueError for invalid arguments that were accepted before, see Stricter Input Validation below.

New Features and Enhancements#

New functions and methods#

  • Add compare_vuong, the Vuong test for non-nested likelihood models, and its result class VuongTestResult. The test supports AIC and BIC corrections and one-sided alternatives. The function is available from statsmodels.stats.api. Issue #3897, PR #10502, PR #10560

  • Add confint_proportions_paired for the confidence interval of the difference of two paired proportions, using Newcombe’s method 10 (the default) or the Wald interval. Issue #10374, PR #10375

  • Add RollingRegressionResults.get_resid to compute the residuals of RollingOLS and RollingWLS, optionally as one-step ahead prediction errors with out_of_sample=True. Issue #7521, PR #10462

  • Add the keyword-only argument effect_group to TreatmentEffect.aipw and TreatmentEffect.aipw_wls to estimate the effect on the treated (ATET) or on the controls (ATC) in addition to the average treatment effect (ATE), which remains the default. Issue #10226, PR #10233

  • Add the methods TreatmentEffect.overlap_summary and TreatmentEffect.balance_table. They report the distribution of the propensity score by treatment group and the covariate balance before and after inverse probability weighting. Issue #10234, PR #10235

  • MNLogit has the documented names attribute that maps the column number of wendog to the name of the category of the endogenous variable. Issue #8995, PR #10486, PR #10558

  • DynamicFactorMQ.fit_em(full_output=True) includes a converged entry in the EM return values, which distinguishes a converged fit from a fit that stopped at maxiter or was reverted. Issue #10157, PR #10214

  • statsmodels.tsa.tsatools.freq_to_period supports sub-daily frequencies, for example hourly data maps to 24 and "5min" to 288, if the multiplier divides the day. It also supports the business month, quarter and year frequencies ("BME", "BQS", "BYE", "CBMS" and similar), which map to the same period as their calendar counterparts, including the older pandas spellings. Issue #9619, Issue #9308, Issue #10525, PR #10401, PR #10528, PR #10542

  • statsmodels.tsa.tsatools.add_lag accepts the label of a column of a pandas DataFrame as col. PR #10302

  • Add the one_sided argument to hpfilter. With one_sided=True, the trend at time t only depends on the observations up to and including t. It is computed with the Kalman filter of the state space form of the HP filter. Issue #6947, PR #10588

Performance#

  • RollingOLS and RollingWLS estimate the windows in batches using stacked linear algebra. The pull request reports speed-ups of 5 to 30 times. Issue #8417, PR #10533

  • The leave-one-observation-out measures of OLSInfluence (dfbeta, dfbetas, dffits, resid_studentized_external, cov_ratio and summary_frame) are computed from closed form updates instead of estimating one regression for each observation if the model is OLS or WLS and exog has full rank. Issue #9009, PR #10367

  • adfuller with autolag selects the lag length from a single QR decomposition and needs much less memory and time for large maxlag. This also applies to coint and zivot_andrews. Issue #1849, PR #10526

  • acorr_ljungbox computes the autocorrelations using the FFT, which is faster for long series. PR #10470

  • robust.scale.qn_scale is about 5 times faster for large samples. PR #10244

  • Lag order selection fits the nested sequence of models from a single blocked QR decomposition, shared by a new private helper. This applies to adfuller with autolag, VAR.select_order, pacf_ols, pacf_yw (Levinson-Durbin) and ardl_select_order. VAR.select_order is 12 to 43 times faster, pacf_ols about 90 times faster for long series, and ardl_select_order evaluates thousands of candidate models in a fraction of a second instead of seconds. pacf_ols with efficient=True demeans the series first, which is more accurate when the mean is large relative to the variation. Issue #2276, PR #10571

  • zivot_andrews computes the regressions of all candidate break periods from one QR decomposition of the regressors that do not depend on the break, using the same private helper, instead of fitting one regression per period. The cost grows linearly instead of quadratically with the number of observations, so the test is about 25 to 65 times faster for 2,000 observations and 50 to 140 times faster for 5,000. The statistics are more accurate when the regressors are close to collinear, so for such series the statistic can change in the later digits. The new values agree with R (urca) and with high-precision arithmetic. Issue #10601, PR #10602

Bug Fixes#

Regression and linear models#

  • OLS.hessian(params, scale=None), the Hessian of the profile (concentrated) log-likelihood, was missing a factor of 2 in the term that involves X'X. The results of OLS.fit_regularized with profile_scale=True change because they use this Hessian. Issue #9469, PR #10473, PR #10556

  • OLSInfluence for the results of a WLS model used the unweighted design matrix and residuals for the hat matrix, the studentized residuals, Cook’s distance, dffits and the leave-one-observation-out measures. These are now computed from the whitened data, which matches R’s influence.measures for lm(..., weights=w). The weights are treated as precision weights. Issue #9067, PR #10476, PR #10563

  • compare_lm_test with cov_type="cluster" returned a Lagrange multiplier statistic that was too small by a factor of nobs. Issue #10284, PR #10286

  • get_prediction(weights=...) of regression results raised “weights has wrong shape” if the number of rows of exog was equal to the number of parameters, and did not check the length of weights against the number of rows otherwise. Issue #10283, PR #10285

  • OLS, WLS, GLS, GLSAR and QuantReg raise a MissingDataError when endog, exog, weights or sigma contain inf or nan after missing values are handled, so that missing="drop" still removes nan but not inf. Before, only nan and inf in exog were detected, and only if hasconst was not False. -inf in exog, and non-finite values of the other arrays, raised a LinAlgError in fit or gave parameters that are all nan. Issue #1642, Issue #3468, PR #4969

  • get_prediction() called without exog now uses the offset and exposure of the model, as predict does, for GLM, GLMGam, the discrete count models and the binary models (Logit and Probit). Before, the offset and the exposure were ignored, so that the predicted mean, the standard errors, the intervals and the influence measures derived from them were wrong. get_prediction(offset=c) keeps the exposure of the model and get_prediction(exposure=c) keeps its offset. PR #10484, PR #10562

  • fit(use_t=True) was ignored with cov_type="nonrobust" (the default) in the discrete models, which used the normal and chi-square distributions. Issue #10307, PR #10327

  • OLS.fit_regularized(L1_wt=0) returns wrapped results, so that the parameters are a pandas Series for pandas data. Issue #4724, PR #10262

  • The results of fit_constrained for a model created from a formula can be pickled. The formula is no longer passed to the transformed model. Issue #9018, PR #10279

  • RecursiveLS with constraints and a NumPy endog either raised an exception or silently dropped the constraints. PR #10282

  • recursive_olsresiduals no longer raises if the initial window is rank deficient, for example because of a duplicated row. The recursion starts from the pseudo-inverse. Issue #8446, PR #10493

  • linear_harvey_collier always dropped the first 3 recursive residuals. The default skip is now the number of regressors, which changes the result for models that do not have 3 regressors. Issue #8446, PR #10291

  • RollingOLS and RollingWLS with missing="skip" returned wrong estimates for the windows after a window with missing values. The number of missing values in each window was off by one and the cross-products were not recomputed after skipped windows. PR #10463

  • RollingOLS and RollingWLS with expanding=True raised an IndexError if window is larger than the number of observations. With expanding=False a ValueError is raised in this case. Issue #9287, PR #10402, PR #10495

  • yule_walker raises a ValueError for a negative order instead of an IndexError. PR #10346

Generalized linear models and discrete models#

  • score_test with a one-dimensional exog_extra for the discrete models and the GLM result method raised an IndexError in 0.15.0. A one-dimensional exog_extra is a single additional variable, as before. PR #10609

  • predict preserves the observation index of a pandas Series for models with one predictor and additional parameters, such as NegativeBinomial, GeneralizedPoisson, ZeroInflatedPoisson, BetaModel, OrderedModel and MNLogit. Previously, multiple observations raised an index length error and a single observation received an incorrect label. PR #10590

  • GEE used the number of columns of exog for df_model, df_resid and the default ddof_scale. These are now based on the rank of exog as in the other models, so that a singular design can no longer produce a negative df_resid or scale. Issue #1928, PR #10278

  • Logit.loglike and Logit.loglikeobs are computed with logaddexp and no longer overflow for large absolute values of the linear predictor. Issue #3923, PR #10217

  • Probit.loglike, loglikeobs, score, score_obs and hessian are computed in log space. The log-likelihood was clipped to a constant and the Hessian was nan for extreme values of the linear predictor. Issue #10228, PR #10229

  • HurdleCountModel.fit ignored the use_t argument. PR #10299

  • MNLogit.get_margeff with dummy=True or count=True failed or returned an incorrect covariance if the number of regressors differs from the number of outcome categories. Issue #5488, PR #10298

Mixed models and imputation#

  • MixedLM returned wrong fixed effects, a scale that was too small, an infinite log-likelihood or failed with a singular matrix error if the random effects covariance or a variance component was at the boundary of the parameter space, i.e. a variance of 0. The degenerate directions are now dropped consistently in get_fe_params, loglike, score, hessian and get_scale, which is the limit as these variances go to zero. Issue #10239, PR #10242, PR #10458

  • MixedLM with missing="drop" raised an IndexError because the rows with missing values were not dropped from all inputs, endog, exog, groups and exog_re. If exog_vc is used and observations are dropped, a ValueError is raised because the variance component design matrices cannot be aligned. Drop the missing values before creating the model, or use from_formula. Issue #7978, PR #10467

  • MixedLM.fit with do_cg=False raised an UnboundLocalError. Issue #7980, PR #10328

  • MixedLM.fit_regularized failed for models with pandas data, for example from a formula: summary raised a KeyError and, with pandas 3, fit_regularized itself failed. Issue #8902, PR #10465

  • MICE.combine failed for results of models that do not have a _results attribute, for example those of PHReg. Issue #9136, PR #10479, PR #10557

Time series analysis#

  • MLEModel.loglike returns -inf instead of raising a LinAlgError if the states are initialized as stationary and the transition matrix has a unit root, so that the stationary covariance of the initial state does not exist. A derivative free optimizer, such as method="powell", can try parameters that are transformed to the boundary of the stationary region. The fit of the dynamic factor model in the example notebook failed with this error on some platforms. PR #10611

  • range_unit_root_test documents the correct null hypothesis, a unit root, which is rejected for small statistics. The InterpolationWarning reports the correct direction: it is raised if the statistic is outside the range of the tabulated critical values, which is 1% to 95%; it was also raised for statistics between the 90% and 95% critical values. Issue #8978, PR #10475, PR #10568

  • UECMResults.bounds_test raised a TypeError for a model without lagged differences of the dependent variable (lags=0). PR #10578

  • arma2ma and arma2ar raised an AttributeError if lags is not given. They default to nobs coefficients. Issue #4464, PR #10466, PR #10569

  • acorr_ljungbox with auto_lag=True selected the wrong lag. The threshold used the lag-0 autocorrelation, which is always 1, so that the penalized criterion was never used, and the index of the maximum was returned instead of the lag. Issue #6785, Issue #8338, Issue #8339, PR #10236

  • adfuller with regression="n" and an even number of observations could choose a maxlag for which the regression fits exactly and the statistic is 0. This made coint return a statistic of 0 and a p-value of 0.9859 for short samples with an even number of observations. The maximum lag now keeps one residual degree of freedom. Issue #9375, PR #10430

  • kpss raises a ValueError for a constant series and a MissingDataError for nan or infinite values. Issue #8224, PR #10432, PR #10306

  • acorr_breusch_godfrey works for the results of AutoReg and ARDL models. It failed with an AttributeError or a length mismatch, and the auxiliary regression omitted the lags and deterministic terms. The results are verified against R’s lmtest::bgtest. Issue #9090, PR #10400

  • The ARDL model defines k_constant, so that rsquared and ess of the results are correct if the model has a constant. PR #10389

  • UECMResults.apply and UECMResults.append return UECM results instead of ARDL results. PR #10293

  • ARIMA.fit(method="innovations_mle", start_params=...) raises a NotImplementedError that points to method="statespace" instead of a TypeError. Issue #8091, PR #10482

  • SARIMAX.start_params failed with an IndexError for a series with a single observation. Issue #9237, PR #10472

  • The summary of SARIMAX printed the list of seasonal MA lags instead of the integer order if the seasonal MA order differs from the non-seasonal MA order. Issue #9490, PR #10231

  • ARIMA, SARIMAX and VARMAX accept a polynomial trend that is a NumPy array. An array that is not one-dimensional with finite numeric values raises the ValueError that lists the valid trends. Issue #9145, PR #10365, PR #10448

  • VARMAX.start_params failed for integer endog with a trend or exog. Issue #9014, PR #10362

  • VARProcess.simulate_var for a stand-alone VARProcess counted the trend terms along the wrong dimension of coefs_exog and failed with an AttributeError. A process with a time trend or exogenous regressors raises a ValueError that requires an offset. Issue #8926, PR #10446

  • The p-values of VECMResults (pvalues_alpha, pvalues_beta, pvalues_gamma, pvalues_det_coef and pvalues_det_coef_coint) are computed with the survival function. They were exactly 0 for large t-values. PR #10445

  • Out-of-sample forecasts of ExponentialSmoothing with a seasonal component discarded the final in-sample update of the seasonal factors and used the factors from one step earlier. Issue #9538, PR #10230

  • For damped trends, the summary and the initial_trend entry of the parameters of the ExponentialSmoothing results reported a value derived from the damped initial trend instead of the estimated initial trend. PR #10294

  • ExponentialSmoothing accepts use_boxcox="log" in the constructor. The value was documented but raised a TypeError. Issue #9135, PR #10361

  • MSTL.fit consumed the inner_iter and outer_iter entries of stl_kwargs, so that a second call of fit used different settings. PR #10292

  • seasonal_plot did not sort the observations of each season, because the result of sort_index was discarded. PR #10275

  • lpol_fima and lpol_fiar returned nan for d = 0 and coefficients with the wrong sign for d < 0. They are computed with the recursion of the coefficients, which is valid for all d. PR #10296, PR #10366

  • companion_matrix no longer modifies the polynomial that is passed in, and accepts a tuple. PR #10289

  • dentonm raises a ValueError if the indicator has fewer observations than required by the benchmark and the frequency. The descriptions of indicator and benchmark in the docstring, low and high frequency, were swapped. PR #10303

  • Time series models ignore a PeriodIndex whose periods are not consecutive, i.e. one with gaps or repeated periods, and issue a ValueWarning, as they already did for a DatetimeIndex without a frequency. Before, such an index was used, and forecasts were labelled with dates from inside the sample. Forecasting now raises an error unless an index is passed. Data with gaps that follow a calendar rule, such as trading days, can use a DatetimeIndex with a matching frequency (e.g. "B" or a CustomBusinessDay); data with missing observations can be reindexed to consecutive periods. Consecutive periods with a frequency multiplier, such as "2Q", are still supported. For an ignored PeriodIndex the “Sample” line of the results summary shows integer positions, e.g. 0 - 19, and model.data.dates is None, as for a DatetimeIndex without a frequency. Issue #6247, Issue #8950, PR #10572, PR #10581

  • The asymptotic critical values and p-values of bounds_test are looked up with the number of regressors, excluding the dependent variable, as in Pesaran, Shin and Smith (2001). They were those for one regressor too many, so the p-values were too small. Models with 10 regressors use the tables instead of simulation. Issue #10546, PR #10574

  • The statistic of bounds_test was computed without the fixed regressors and the seasonal terms of the model, so that it did not depend on them. They are now included as controls, and the statistic matches R’s ARDL::bounds_f_test. A model that uses deterministic raises a NotImplementedError instead of ignoring the process. PR #10579

  • x13_arima_analysis reads a rawspec file as UTF-8 independent of the locale. Before, the file was decoded with the locale encoding, so that text with non-ASCII characters was garbled or failed, for example on Windows. A UTF-8 byte order mark is ignored, a file that is not valid UTF-8 raises a ValueError that says so, and rawspec accepts a pathlib.Path as documented. PR #10585

  • coint_johansen, select_coint_rank and the error bands of the impulse responses of a VAR returned complex eigenvalues and eigenvectors with NumPy 2.5 and later, which np.linalg.eig returns as complex arrays even if all the eigenvalues are real, and coint_johansen warned with a ComplexWarning. The results are real again. PR #10613

  • smoothed_state_autocovariance does not warn that the univariate filter diagonalized the observation covariance when it extends the model beyond the sample, since it does not use the disturbance covariances. PR #10613

  • arma_order_select_ic no longer warns about the starting values of the candidate models that fall back to zeros. PR #10613

  • hamilton_filter and the starting values of DynamicFactorMQ no longer warn about the unused scale of a regression without residual degrees of freedom. PR #10613

  • ThetaModelResults.plot_predict with alpha=None no longer adds a legend without labels, which warned. PR #10613

  • SVAR.sirf_errband_mc and IRAnalysis.errband_mc with svar=True show one ConvergenceWarning with the number of replications whose maximum likelihood fit did not converge, instead of one warning for each of them. PR #10613

Statistics and tests#

  • statsmodels.stats.power validates that a root returned by a solver attains the requested power. Failed solutions now return NaN with a ConvergenceWarning instead of returning a misleading finite result or raising an error, also when solving for alpha, which now finds significance levels far below 1e-5. Noncentral-t CDF calculations retry a reflected tail when CDFLIB returns NaN and use the limit 0 or 1 if that fails too, preserving already finite values. This can turn previously missing t-test powers into finite results; it does not guarantee relative accuracy in extremely small tails. PR #10552

  • The p-values of several tests were computed as one minus the cdf, which gives 0 or loses digits for large statistics. They now use the survival function. This affects survdiff, the empirical likelihood ANOVA and OLSResults.el_test, the GEE score tests, the chi-square tests of Table, SquareTable and StratifiedTable, the p-values of the UECM long-run coefficients and the bounds test of ARDL, and the distance covariance test. Issue #10274, PR #10276

  • DescrStatsW, CompareMeans and the functions that use them no longer overflow in the variance and in the standard errors of the mean difference for data with a large scale if the result is representable. Issue #10252, PR #10255

  • DescrStatsW rejects weights that are negative or not finite with a ValueError. Non-finite weights gave nan or ignored the weight in quantile. PR #10355, PR #10371

  • StratifiedTable.test_null_odds(correction=True) applies the continuity correction of 0.5 only if |sum(a - E(a))| >= 0.5, as mantelhaen.test of R does. Before, min(0.5, |sum(a - E(a))|) was subtracted, which changed the statistic when the deviation is below 0.5. The statistic and the p-value of a table with zero variance are nan, they were inf and 0. PR #10551, PR #10583

  • The DerSimonian-Laird estimate of the between-study variance in combine_effects (method_re="dl" or "chi2") is truncated at zero. A negative variance was used before, which could give a random effects mean outside the range of the effects. The h2 and i2 attributes of the results are at least 1 and 0, as in R’s metafor. They were below 1 and negative if q < k - 1. combine_effects accepts lists and tuples. Issue #10520, PR #10522, PR #10555

  • effectsize_2proportions applied the zero-cell continuity correction to all studies if any study had a zero cell. It is now applied only to the studies with a zero cell. With zero_correction="tac", the constants of the two samples were swapped and the sample sizes increased by the wrong amount, which gave a nonzero effect for a study without events in both samples if the sample sizes differ. Lists and tuples are accepted with zero_correction="tac". Issue #10290, PR #10301, PR #10366

  • The Miettinen-Nurminen score test of the difference of two proportions (method="score" and compare="diff" in test_proportions_2indep and confint_proportions_2indep) used a wrong linear coefficient in the constrained maximum likelihood estimate if the null value is not 0. The score test also returned nan for symmetric tables. The root finding for the confidence interval of the difference could start outside of the parameter space. Issue #10269, PR #10270, PR #10366

  • power_equivalence_poisson_2indep and power_equivalence_neginb_2indep returned wrong results if nobs_ratio is not 1. The ftotal null variance of power_equivalence_neginb_2indep and power_negbin_ratio_2indep is equal to the score variance if dispersion=0. A nobs_ratio that is not positive and finite raises a ValueError in the two equivalence functions. Issue #10519, PR #10521, PR #10555

  • effectsize_oneway with a scalar vars_ and use_var="bf" returned an infinite effect size. PR #10455

  • The default value of power_poisson_ratio_2indep is now 1, the null hypothesis of equal rates. The previous default of 0 gave a power of 0, 1 or nan. The value must now be positive and finite. power_negbin_ratio_2indep has the same check; value=0 gave a divide by zero warning, and value=inf was accepted by both functions. Issue #10511, PR #10512, PR #10550, PR #10580

  • power_binom_tost returns a power of 0 instead of a negative value if the rejection region of the exact test is empty. low and upp also accept list-like input, and a NaN p_alt raises a ValueError. Issue #10507, PR #10508, PR #10580

  • TTestIndPower.power and TTestIndPower.solve_power accept ratio=0, which gives the power of the one-sample t-test with nobs1 observations; it raised a ZeroDivisionError or gave the size of the test for NumPy scalars. ratio can be array_like, and a negative or NaN ratio raises a ValueError; solve_power returned nan with a convergence warning for a negative ratio. PR #10349, PR #10584

  • proportions_chisquare raises a ValueError for a single sample without value. The statistic was 0 and the p-value nan. PR #10451

  • StratifiedTable.test_equal_odds (Breslow-Day and Tarone tests) returned nan or an inaccurate statistic when the pooled odds ratio is one or very close to one, and for tables with small fitted cells. The statistic is now computed accurately in these cases. PR #10540

  • gof_chisquare_discrete and gof_binning_discrete no longer restrict the support of the distribution to the range -1000 to 1000. The bins are chosen using the quantile function. The bins work for distributions for which the ppf of SciPy fails to converge, such as skellam with large parameters, and for edges of about 1e9 and larger. nsupp below 1 raises a ValueError. Issue #4359, PR #10529, PR #10555

  • rmspe truncated the percentage errors for integer input. Issue #10509, PR #10510

  • cov_cluster raised a ZeroDivisionError for a single cluster. It now raises a ValueError that requires at least 2 clusters. PR #10496

  • summary_col with fixed_effects placed the fixed effects indicator rows after the rows of info_dict. They are placed after the parameter rows and before the model info rows. Issue #9282, PR #10218

  • corr_rank and corr_normal_scores return a 1 by 1 matrix for a single variable instead of a scalar. PR #10456

  • Description no longer calls scipy.stats.mode for a column without observations, which warns in SciPy 1.14 and later. PR #10613

Treatment effects#

  • TreatmentEffect clipped the propensity score inconsistently. The point estimates used the unclipped propensity score, while the GMM moment conditions of ipw and aipw clipped at 0.01 and 0.99 and those of aipw_wls and ipw_ra clipped at 0.001 and 0.999. The new argument ps_bounds (default (0.001, 0.999)) sets the bounds, which are now used for the point estimates and the inference of all methods. Results change if the estimated propensity score is outside of the bounds. Issue #10222, PR #10223

  • The GMM moment conditions of aipw_wls and ipw_ra assumed that the propensity score model has 6 parameters. They now use the number of parameters of the selection model. PR #10221

Robust and multivariate statistics#

  • CovDetMCD, CovDetS and CovDetMM raised a ValueError (“Percentiles must be in the range [0, 100]”) if nobs < 2 * k_vars + 4. Issue #10241, PR #10247

  • CovDetMCD, CovDetS and CovDetMM failed for data with a single column, and cov_ogk and cov_tyler_regularized did not handle a single variable. Issue #10300, PR #10330, PR #10456

  • CovDetMCD ranked the starting sets by the determinant, which overflows for moderately large k_vars, and then selected the first starting set. The ranking uses the log determinant. The determinant used to normalize the covariance in cov_weighted (weights_cov_denom="det"), cov_tyler (normalize="det") and CovM is computed without overflow. Issue #10295, Issue #10257, PR #10329, PR #10287

  • The deterministic starting sets of CovDetMCD, CovDetS and CovDetMM were ranked with a wrong Mahalanobis distance, because mahalanobis was called with the mean in place of the covariance. The estimates can change slightly. PR #10457

  • CovDetS and CovDetMM ignored their breakdown_point argument and always used 0.5 for the tuning constant of the first-stage S-estimator. Values outside (0, 0.5] now raise a ValueError, and small values in higher dimension no longer fail. PR #10468, PR #10564

  • CovDetMCD raises a ValueError if the covariance of the selected subset is numerically singular, for example if at least h observations lie on a hyperplane, or if h is not larger than the number of variables. Before, the fit returned a result with a singular covariance. Issue #10437, PR #10464, PR #10570

  • The Ledoit-Wolf starting estimate of the deterministic estimators omitted the shrinkage target, and divided by zero for a single variable. Issue #10368, PR #10378, PR #10452

  • CovDetMCD, CovDetS and CovDetMM raise a ValueError that names the column if the standardizing scale of a column is zero, i.e. more than half of the observations share one value. Issue #10437, PR #10461

  • robust.covariance.mahalanobis uses the pseudo-inverse if cov is numerically singular. Before, this was only done if the inverse failed, and a rank deficient matrix could return values of the order of 1e16 on some platforms. PR #10376

  • qn_scale returns nan if the data contain nan or infinite values. It returned a finite value or failed before. The underlying implementation no longer crashes for samples with 46341 or more observations. PR #10372, PR #10244

  • PCA with gls=True applied the weights inverted: the data were divided by the square root of the weights instead of multiplied by it. Issue #10256, PR #10258

  • Factor with method="ml" and PHD returned complex loadings and directions with NumPy 2.5 and later, which np.linalg.eig returns as complex arrays even if all the eigenvalues are real. The results are real again. PR #10613

Nonparametric#

  • The tricube kernel in statsmodels.nonparametric.kernels returns 0 outside of its support, \(|u| > 1\), instead of the peak value. Results of KernelReg and KernelCensoredReg that use ckertype="tricube" change. Scalar arguments are accepted. Issue #10541, PR #10547, PR #10550

  • pdf_kernel_asym and cdf_kernel_asym no longer raise ZeroDivisionError (array x) or TypeError (scalar x) when the sample has more than batch_size * 1000 observations (10 000 with the default). Intermediate kernel arrays never exceed batch_size * 1000 elements, because the sample is split as well as the evaluation points. batch_size must be a number with batch_size * 1000 >= 1, and a one-element x, including a Series, returns a scalar. PR #10577, PR #10582

  • A scalar user-specified bandwidth is accepted by KDEMultivariate, KDEMultivariateConditional, KernelReg and KernelCensoredReg. Issue #4747, PR #10272

  • The bandwidth of KDEMultivariate and KernelReg is validated. A user-specified bandwidth has to be positive, or non-negative for KernelReg where 0 is allowed for discrete variables, and an unknown bandwidth method raises a ValueError. In KernelReg, any string other than "cv_ls" selected the AIC bandwidth, including "normal_reference" which now uses the normal reference rule of thumb. PR #10412

  • fast_linbin, used by KDEUnivariate.fit(fft=True), wrote outside of its array for some inputs and dropped observations at the upper end of the grid. Issue #9556, PR #10232

Duration models#

  • The Schoenfeld, score and martingale residuals of PHReg with ties="efron" used the Breslow approximation of the ties. They now use the approximation of the model and match R’s survival::coxph. The sum of the score residuals is the score of the partial likelihood, and the cluster robust covariance, which is built from the score residuals, was wrong with Efron ties. Observations that are not at risk at any failure time have a score residual of 0 (they were added to the risk set of the preceding failure time before). Observations that are not used no longer produce a nan robust covariance. Issue #10288, PR #10363, PR #10377

  • SurvfuncRight with exog and integer times stored an arbitrary integer instead of nan in surv_prob_se, n_risk and n_events, and warned about casting nan to an integer. They are nan as floats. PR #10613

Other#

  • missing="drop" with a boolean endog failed with “Data must be 1-dimensional”. Issue #5445, PR #10477

  • ExpandedNormal no longer modifies the array of cumulants that is passed in. PR #10281

Stricter Input Validation#

The following functions and methods now raise a ValueError for arguments that are outside of their valid range. Depending on the function, invalid values returned nan, inf or a meaningless number, or failed with an unrelated exception, for example a bare NumPy error or an IndexError. Functions that broadcast over an argument continue to accept arrays, and reject arrays that contain an invalid value or nan.

Confidence level and significance#

  • alpha must be in the interval (0, 1) in: conf_int of the results of the models, of the prediction results and of the contrast results, zconfint, the t and z confidence intervals of DescrStatsW and CompareMeans, proportion_confint, multinomial_proportions_confint, confint_proportions_2indep, the Table2x2 confidence intervals, confint_poisson, tolerance_int_poisson, confint_quantile_poisson, confint_mvmean_fromstats, confint_noncentrality, combine_effects, tukeyhsd, the confidence intervals of acf, pacf, ccf and pccf, multipletests and fdrcorrection_twostage. fdrcorrection accepts values in (0, 1]. signif of VARResults.test_whiteness has to be in (0, 1). The p-values that are passed to multipletests have to be in [0, 1]. PR #10391, PR #10433, PR #10392, PR #10403, PR #10380, PR #10397, PR #10399, PR #10379, PR #10413, PR #10384, PR #10415, PR #10333, PR #10390, PR #10338, PR #10310, PR #10410

  • The power functions and classes of statsmodels.stats.power (TTestPower, TTestIndPower, NormalIndPower, FTestPower, FTestPowerF2, FTestAnovaPower, ttest_power, normal_power, normal_power_het, ftest_anova_power, ftest_power and ftest_power_f2) check alpha, and the F test classes check df_num and df_denom. The two-sample Poisson and negative binomial power functions in statsmodels.stats.rates check alpha and nobs1, chisquare_power checks nobs, n_bins and alpha, and samplesize_proportions_2indep_onetail checks alpha and power. PR #10393, PR #10447, PR #10386, PR #10385, PR #10388

Counts, sample sizes, weights and probabilities#

  • Counts must be non-negative and not larger than nobs, and nobs and exposures must be positive, in: proportion_confint, binom_test, proportions_ztest, proportions_chisquare, confint_proportions_2indep, effectsize_2proportions, test_poisson, test_poisson_2indep, etest_poisson_2indep, confint_poisson_2indep and the one-sample Poisson rate functions. value of proportions_ztest and proportions_chisquare has to be finite and in the valid range, and prop_var of proportions_ztest in (0, 1). PR #10380, PR #10360, PR #10358, PR #10414, PR #10345, PR #10354, PR #10373, PR #10379, PR #10388, PR #10398

  • The proportions of proportion_effectsize have to be in [0, 1], the arguments diff and prop2 of power_proportions_2indep and samplesize_proportions_2indep_onetail have to keep both proportions in [0, 1], and the probabilities of chisquare_effectsize have to be non-negative. PR #10383, PR #10431, PR #10425, PR #10395

  • samplesize_confint_proportion checks its arguments: alpha has to be in (0, 1), half_length positive and proportion in [0, 1]. Invalid values, including nan in arrays, raise a ValueError. They returned inf, nan, the sample size of abs(half_length) or a negative sample size. Lists are accepted. PR #10381

  • The dispersion of the Poisson and negative binomial power functions in statsmodels.stats.rates has to be non-negative. alpha of the NegativeBinomial link in statsmodels.genmod.families.links has to be positive. PR #10422, PR #10426, PR #10357

  • The cell counts of Table, StratifiedTable and mcnemar have to be finite and non-negative. PR #10332, PR #10350, PR #10370

  • probs of DescrStatsW.quantile has to be in [0, 1] and ddof of ztest and zconfint has to be non-negative. PR #10404, PR #10405

  • nobs has to be positive in test_cov_spherical, test_cov_diagonal, test_cov_blockdiagonal, test_cov_oneway, confint_mvmean_fromstats and confint_effectsize_oneway, and effectsize_oneway requires non-negative vars_ and positive nobs. PR #10423, PR #10433, PR #10408, PR #10356

  • The variances in combine_effects, the diagonal of cov in cov2corr and the standard deviations in corr2cov have to be non-negative. PR #10415, PR #10417

Intervals, tuning parameters and shapes#

  • Equivalence intervals have to satisfy low < upp (low <= upp for the Poisson functions) in the TOST methods of DescrStatsW and CompareMeans, ttost_paired, ztost, binom_tost, proportions_ztost, binom_tost_reject_interval, power_binom_tost, power_ztost_prop, tost_poisson_2indep, nonequivalence_poisson_2indep and the Poisson and negative binomial equivalence power functions. equiv_margin of equivalence_oneway has to be positive and p_alt of power_binom_tost and power_ztost_prop has to be in [0, 1]. PR #10334, PR #10382, PR #10406, PR #10411, PR #10421, PR #10420

  • c of mad and iqr has to be positive, the percentile bands of robust_kurtosis have to be ordered, scale of GLM.fit has to be positive, exposure of GLM.predict has to be positive and the length of offset of the binary discrete models has to match endog. PR #10419, PR #10416, PR #10394, PR #10428, PR #10352

  • bw of KDEUnivariate.fit has to be positive, ncomp of PCA has to be positive, nlags of cov_hac and S_hac_simple has to be non-negative, degree of reset_ramsey has to be at least 2, exog_idx of variance_inflation_factor and axis of omni_normtest are checked, and local_fdr checks deg and nbins. PR #10396, PR #10341, PR #10344, PR #10343, PR #10424, PR #10347, PR #10348

  • het_goldfeldquandt checks split and that both subsamples have residual degrees of freedom, compare_cox and compare_j check that the two models use the same number of observations, and fleiss_kappa, cohens_kappa and to_table check the shape of their input. PR #10342, PR #10369, PR #10351, PR #10314, PR #10315, PR #10316

  • The tuning constants of the robust norms in statsmodels.robust.norms are validated. t of HuberT, a of RamsayE and AndrewWave, c of TrimmedMean, TukeyBiweight, TukeyQuartic and StudentT, and df of StudentT have to be positive, k of TukeyQuartic has to be a positive even integer, q of MQuantileNorm has to be in (0, 1), and the constants of Hampel have to be scalars with 0 < a <= b <= c. Zero, negative and nan values used to create norms with an all-zero or nan psi, and array valued constants of Hampel failed in every method. The check applies to the constructor and to _set_tuning_param, attributes that are assigned later are not checked. Arguments of the wrong type, for example None, a string or a complex number, raise a TypeError. PR #10418

Time series#

  • nlags has to be non-negative in pacf, kpss and levinson_durbin, and smaller than the number of observations in acf and acorr_breusch_godfrey. ccf checks nlags against the number of observations, acovf requires a non-negative nlag, levinson_durbin raises if fewer autocovariances than lags are available, nobs of arma_acovf has to be positive and nobs of q_stat has to be larger than the number of lags. PR #10317, PR #10319, PR #10335, PR #10337, PR #10321, PR #10318, PR #10320, PR #10297, PR #10336, PR #10409

  • max_ar and max_ma of arma_order_select_ic have to be non-negative, maxlags of VAR.fit and vecm.select_order has to be non-negative (and smaller than the number of observations for VAR.fit), and steps of the VAR forecasts and periods of VARResults.irf have to be non-negative. PR #10353, PR #10322, PR #10339, PR #10429

  • period of seasonal_decompose and ThetaModel has to be at least 2, order of detrend has to be non-negative, lamb of hpfilter has to be positive, bkfilter requires low < high and more than 2 * K observations, and cffilter requires low < high. PR #10309, PR #10359, PR #10323, PR #10305, PR #10304

  • The smoothing and damping parameters of ExponentialSmoothing.fit have to be in [0, 1]. PR #10387
